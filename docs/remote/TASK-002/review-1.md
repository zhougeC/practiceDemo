### 兼容性、需求边界与交付决策

**R-C15 / P1 — WebGL2 是待裁决的支持范围，不应一边待裁决一边作为不可变实施前提。**  
**条款：** task §2.1–2.2；设计 M-06、ADR-02、Q1、P0/P1。  
选择 r170 + WebGL2 并非天然错误，也不要求为了 WebGL1 自研；但“2026 年主流设备都支持”不是已验证覆盖证据。原契约只明确“无 WebGL”提示，v1 则让**有 WebGL1、无 WebGL2**的设备完全不可用。  
**问 Opus：** 请明确这是需要用户批准的支持范围取舍，列出目标浏览器/最低版本及 WebGL1-only 行为；如不批准，给出不自研的替代方案和涉及 shader 的差异。  
**验收：** WebGL2 正常、WebGL1-only、完全无 WebGL 三种能力分别有明确预期；不得把 WebGL1-only 记成“无 WebGL”，也不得在裁决前称兼容性已满足。

**R-C16 / P2 — vendoring 路径合理，但构建产物契约还不完整。**  
**条款：** P0、ADR-01、R1、§5.5。  
IIFE 本地经典脚本符合 `file://` 离线方向，不能因尚未实测就认定打包失败。不过 `three` 锁定了版本，`npx esbuild` 未锁版本；只有生成命令和产物 hash，缺少打包工具版本及可核对的输入记录。三方 ≤800 KB 又是硬预算，文中预计值尚未验证。  
**问 Opus：** 能否锁定工具版本，明确生成目录、许可证、输入/输出 hash、体积超标的升级处理，以及最终提交哪些文件？  
**验收：** 用约定命令获得完整 vendor 文件；交付后脱离 npm、服务器和网络，直接打开入口工作；检查产物没有运行时 import、资源下载或 source-map 网络依赖。体积报告区分应用源码与 vendor。

**R-C17 / P2 — “任意输入”被主动缩窄。**  
**条款：** task #12；§4.6.1、ADR-12、Q3。  
无按压 pointermove 被排除，事件范围又限于按钮/画布；用户移动鼠标或操作其他 HUD 区域时，按当前规则可能不打断 AUTO。这是需求解释的待裁决项，不是已满足“任意输入”。  
**问 Opus：** 请请求用户明确输入集合，或默认遵守字面要求；区分真正用户事件与程序生成事件，并定义 HUD 上的交互。  
**验收：** 用明确输入矩阵覆盖任意键、鼠标移动/滚轮、画布拖动、触屏按钮、成就列表操作，每项标记打断和恢复规则。

**R-C18 / P2 — 部分必须写死的规格仍缺少可实施定义。**  
**条款：** D2/D5、§1.1、§4.2.2、§4.3、§4.6.3、§4.7。  
具体缺口包括：rebase 后累计里程/best 的所有权；`lightTerm` 的公式；主光方向公式中的 `…` 及日出区间的切换；自动驾驶 `tArr≈0.36` 的容差/跨阈值规则；自由镜头 yaw 的范围；电影镜头方位角参考轴。尤其自动驾驶只每 0.25 秒决策，若用“接近0.36”且没有跨阈值判定，可从 tArr=.50 跳到 .25，漏掉起跳。  
**问 Opus：** 请补成确定参数和状态转移，不能让实施者在 MUST 接口上自行猜测。  
**验收：** 不同决策相位的 high 鱼接近过程都能触发一次计划起跳；所有公式无省略号、未定义符号或未定义近似关系。

### 接受的设计优点

- **十二项功能保持独立追溯**，没有直接删掉成就、布料、音频、触屏或自动驾驶。
- **本地化 three + 经典脚本 + 程序化资源**适合纯静态、离线、`file://` 交付；正确纠正了“远端不能联网所以必须自研渲染器”的前提。
- **鱼 pose 单源、海面位移函数共享、颜色空间显式处理**方向正确；需要修正的是相邻变换、时序和数学定义，而不是推倒这些结构。
- **指针映射与动作计数、lostpointercapture、隐藏/失焦清理、刹车优先**直接覆盖了既有高风险类别。
- **互斥 overlay、音频恢复门禁、localStorage 失败降级**有清晰意图。
- **离散画质、滞回、DPR 重算、性能预算、截图状态与真机待验证声明**提供了有价值的实施及验收骨架。
